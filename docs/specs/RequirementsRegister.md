# Requirements Register

*Last updated: 2026‑11‑15 (aligned with official baseline SRS v1.3)*

| ID | Requirement | Category | Related Entity | Status | Notes |
|----|-------------|----------|----------------|--------|-------|
| FR-001 | User can register (providing full name, email, password) and log in. User's full name is the primary display identifier. System supports self-service password reset and admin-assisted reset. New users receive Inventory Clerk role by default. | Mandatory | User, Role | Approved | Full name stored on User (Decision U-06); self-service password reset via `POST /auth/forgot-password` & `POST /auth/reset-password` (Decision U-13); bcrypt password hashing; JWT access (15 min) & refresh (7‑day, rotated) cookies. |
| FR-002 | System enforces role‑based access control for all API endpoints. | Mandatory | Role, User | Approved | Admin, InventoryClerk, Manager, FinanceOfficer roles. See RBAC matrix in SRS Appendix A. |
| FR-003 | CRUD operations for inventory items with automatic unique SKU generation and soft deletion safeguards. Deletion restricted when item is referenced by requisitions. | Mandatory | Item | Approved | System automatically generates unique SKU on creation (Decision U-07). Catalog updates (`PATCH /items/:id`) modify metadata/thresholds but cannot alter `quantity`. Soft deletion via `isActive = false` with UI confirmation dialog (Decision U-08). Deleted items hidden by default; accessible to Admin. |
| FR-004 | Inventory Clerk can create and immediately submit a purchase requisition with one or more line items (no draft state). `totalAmount` computed as Σ(requestedQty × snapshotted unitPrice). | Mandatory | Requisition, RequisitionItem | Approved | Immediate submission into `Pending` status upon creation; no Draft state or Save Draft functionality exists (Decision U-01). `snapshotUnitPrice` captured at creation. `approvedQty` defaults to `requestedQty`. |
| FR-005 | Manager can approve or reject a pending requisition (first‑level). May modify `approvedQty` via dedicated "Approve with Changes" dialog. | Mandatory | Requisition, AuditLog | Approved | Reviewers use "Approve with Changes" dialog to adjust quantities and review recalculated total before confirming (Decision U-04). Quantity modification bounds (reduction-only vs. upward) are an unresolved business rule. On rejection: reason required; creator may resubmit via `PATCH /requisitions/:id/resubmit` (captures fresh snapshot price). Status transitions use `SELECT FOR UPDATE`. |
| FR-006 | Finance Officer can approve or reject a Manager‑approved requisition (second‑level). May modify `approvedQty` via "Approve with Changes" dialog. | Mandatory | Requisition, AuditLog | Approved | Quantity modifications use "Approve with Changes" dialog (Decision U-04). Quantity modification bounds are an unresolved business rule. On rejection: reason required; creator may resubmit via `PATCH /requisitions/:id/resubmit` (restarts at Pending with fresh price snapshot). Status transitions use `SELECT FOR UPDATE`. |
| FR-007 | Inventory Clerk records physical goods receipt against FinanceApproved orders by entering actual received quantities, supporting partial delivery and four-step excess authorization. | Mandatory | Requisition, Item, AuditLog | Approved | Clerk enters actual `receivedQty` and confirms receipt (Decision U-05); partial delivery (`receivedQty < approvedQty`) allowed directly (Decision U-05.1); excess delivery (`receivedQty > approvedQty`) executes via 4-step sequence: Clerk submits request, Manager operational approval, Finance financial authorization, Clerk final receipt (Decisions U-05.1, U-05.2). Handling of excess rejection by reviewers is an unresolved business decision. |
| FR-008 | System generates low‑stock alert notifications for Manager and Finance Officer on threshold crossing (once per crossing, no duplicates). | Mandatory | Item, Notification | Approved | Fires on any quantity‑changing operation. Mock email via console log. |
| FR-009 | Real‑time updates pushed to front‑end via SSE. Requires JWT authentication via HttpOnly cookie. | Mandatory | Item, Requisition, Notification | Approved | Typed events including `dashboard.updated`. See SSE Event Specification in SRS §4.4. |
| FR-010 | Dashboard displays totals, low‑stock count, recent requisitions, and role-tailored activity feed via `GET /dashboard`; stays updated via `dashboard.updated` SSE event. | Mandatory | Item, Requisition | Approved | Shared layout with role-specific activity feed (Decision U-11). Frontend replaces local state with SSE payload. |
| FR-011 | Authorized management roles (Admin, Manager, Finance Officer) can export inventory to Google Sheet via Quick Export or configurable Custom Export. | Mandatory | Item | Approved | Quick Export uses default settings (exact default columns/scope are implementation defaults subject to PO confirmation); Custom Export opens configuration dialog to select columns and filter scope (all vs filtered) (Decision U-12). Returns `{ sheetUrl }` on success (HTTP 200); HTTP 502 on failure with CSV fallback. |
| FR-012 | System provides OpenAPI (Swagger) documentation at `/api/docs`. | Mandatory | — | Approved | Auto‑generated from NestJS decorators. |
| ~~FR-013~~ | ~~CI/CD pipeline.~~ | ~~Mandatory~~ | ~~—~~ | Removed | Removed — development‑process activity, not system behaviour. |
| FR-014 | Audit log records all state‑changing operations with before/after snapshots and actor full name. | Mandatory | AuditLog | Approved | Primary identifier is actor full name (Decision U-06); soft-deleted item references preserved (Decision U-08); immutable JSON details. |
| FR-015 | Optional: SMA demand forecasting per SKU on dashboard. | Optional | Item | Proposed | Can be omitted if time‑constrained. |
| FR-016 | Good‑to‑have: Interactive Chart.js visualisations. | Good‑to‑have | — | Proposed | Charts can be added after core flow is stable. |
| FR-017 | Notification history, navigation & read status. Clicking a notification navigates directly to target entity and highlights relevant information. | Mandatory | Notification | Approved | Payload stores destination context (`entityType`, `entityId`); destination route and target highlight section are derived deterministically in combination with notification type (Decision U-10). Paginated inbox filtering with single (`PATCH /notifications/:id/read`) and bulk (`PATCH /notifications/read`) mark-as-read. |
| FR-018 | Login endpoint rate‑limiting: max 5 attempts per IP per minute; 6th returns HTTP 429. | Mandatory | User | Approved | Prevents brute‑force attacks. |
| FR-019 | CSRF protection via double‑submit cookie pattern. | Mandatory | — | Approved | Non‑HttpOnly `csrfToken` cookie + `X‑CSRF‑Token` header. Missing/invalid → HTTP 403. |
| FR-020 | Input validation & sanitisation against typed DTOs. | Mandatory | — | Approved | Invalid → HTTP 400; strings escaped before DB insertion. |
| FR-021 | Standardized pagination (`page`, `limit`), domain filtering, and role-specific predefined views for list endpoints. | Mandatory | Item, Requisition | Approved | Shared Requisition List screen with role-specific filter presets: Clerk (All, My Requisitions); Manager (Pending Manager, Reviewed, All); Finance (Pending Finance, Reviewed, All); Admin (All) (Decisions U-03, U-09). Query params `page` (default 1) and `limit` (default 50, max 100); response envelope `{ data: [...], pagination: { page, limit, totalCount, totalPages } }`. |
| FR-022 | SSE connection throttling: max 3 concurrent `/events` streams per user. | Mandatory | — | Approved | Excess connections receive HTTP 429. |
| FR-023 | User Management API: list users, change role, deactivate/reactivate, password reset. Cannot self‑deactivate; last‑Admin guard. | Mandatory | User, Role | Approved | Admin‑only. Deactivation invalidates refresh tokens; HTTP 409 if last Admin. |
| FR-024 | Requisition cancellation: creator may cancel own Pending requisition. Status → Cancelled (terminal). | Mandatory | Requisition, AuditLog | Approved | Cancellation applies strictly to creator's own Pending requisitions; no draft state exists (Decision U-01). Notification sent to Manager and Finance. |
| FR-025 | Manual stock adjustment: signed integer via `PATCH /items/:id/adjust`. Rejects if result < 0. Triggers alert evaluation. | Mandatory | Item, AuditLog | Approved | Admin and Clerk only. `adjustmentReason` required. |
| FR-026 | Standalone CSV export & fallback: `GET /export/csv` available to all authenticated roles for physical counts, planning, and audits (also served as fallback on Sheets API failure). | Mandatory | Item | Approved | Returns direct CSV stream; HTTP 502 with CSV download link if called as fallback from Google Sheets. |
| FR-027 | Refresh token endpoint: `POST /auth/refresh` with rotation. 7‑day expiry. Old token invalidated. | Mandatory | User | Approved | Prevents token reuse. |
| FR-028 | Logout endpoint: `POST /auth/logout` invalidates refresh token, clears cookie. | Mandatory | User | Approved | Immediate session termination. |
| FR-029 | Password recovery mechanisms: self-service email-based reset and Admin-initiated reset via `PATCH /users/:id/reset-password`. | Mandatory | User | Approved | Both self-service recovery via email reset tokens (mocked) and Admin assistance temporary password generation are supported (Decision U-13). In accordance with NFR-009, credentials must never be logged; exact secure credential handoff mechanism is an unresolved implementation detail. |
| FR-030 | Dashboard aggregation endpoint: `GET /dashboard` returns totals, low‑stock count, recent requisitions, and role-specific activity feed. | Mandatory | Item, Requisition | Approved | Role-tailored activity feed embedded in aggregate response (Decision U-11). On‑demand computation; SSE `dashboard.updated` event keeps it current. |
