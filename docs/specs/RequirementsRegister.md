# Requirements Register

**Document Version:** 1.5 – Active  
**Date:** 2026-11-16  
**Aligned With:** SRS v1.5, Data Model v1.5, Decision Log v1.5, SAD v1.0

| ID | Requirement | Category | Related Entity | Status | Notes |
|----|-------------|----------|----------------|--------|-------|
| FR-001 | User can register (providing full name, email, password) and log in. User's full name is the primary display identifier. System supports self-service password reset and admin-assisted reset. New users receive Inventory Clerk role by default. | Mandatory | User, Role | Approved | Full name stored on User (Decision U-06); self-service password reset via `POST /auth/forgot-password` & `POST /auth/reset-password` (routed in dev to secure in-memory mailbox without token logging per NFR-009; Decision U-13); bcrypt password hashing; JWT access (15 min) & refresh (7‑day, rotated) cookies. |
| FR-002 | System enforces role‑based access control for all API endpoints. | Mandatory | Role, User | Approved | Admin, InventoryClerk, Manager, FinanceOfficer roles. See RBAC matrix in SRS Appendix A. |
| FR-003 | CRUD operations for inventory items with automatic unique SKU generation and soft deletion safeguards. Deletion restricted when item is referenced by requisitions. | Mandatory | Item | Approved | System automatically generates unique SKU on creation (Decision U-07). Catalog updates (`PATCH /items/:id`) modify metadata/thresholds but cannot alter `quantity`. Soft deletion via `isActive = false` with UI confirmation dialog (Decision U-08). Deleted items hidden by default; accessible to Admin. |
| FR-004 | Inventory Clerk can create and immediately submit a purchase requisition with one or more line items (no draft state). `totalAmount` computed as Σ(requestedQty × snapshotted unitPrice). | Mandatory | Requisition, RequisitionItem | Approved | Immediate submission into `Pending` status upon creation; no Draft state or Save Draft functionality exists (Decision U-01). `snapshotUnitPrice` captured at creation. `approvedQty` defaults to `requestedQty`. |
| FR-005 | Manager can approve or reject a pending requisition (first‑level). Reviewers cannot modify quantities (Decision UD-03, superseding U-04). | Mandatory | Requisition, AuditLog | Approved | Reviewers cannot alter quantities during approval; if changes are required, Manager must reject with mandatory non-empty reason; creator submits new requisition with corrected quantities via `POST /requisitions` (Decision UD-03). Obsolete "Approve with Changes" dialog removed. |
| FR-006 | Finance Officer can approve or reject a Manager‑approved requisition (second‑level). Reviewers cannot modify quantities (Decision UD-03, superseding U-04). | Mandatory | Requisition, AuditLog | Approved | Reviewers cannot alter quantities during approval; if changes are required, Finance Officer must reject with mandatory non-empty reason; creator submits new requisition with corrected quantities via `POST /requisitions` (Decision UD-03). Obsolete "Approve with Changes" dialog removed. |
| FR-007 | Inventory Clerk records physical goods receipt against FinanceApproved orders by entering actual received quantities, supporting single-event partial delivery and four-step excess authorization with rejection handling. | Mandatory | Requisition, Item, AuditLog | Approved | Clerk enters actual `receivedQty` and confirms receipt (Decision U-05); partial delivery (`receivedQty < approvedQty`) allowed directly, transitioning to `Received`; MVP limitation: exactly one receipt event per requisition, undelivered quantity not tracked (Decision U-05.1); excess delivery (`receivedQty > approvedQty`) executes via 4-step sequence: Clerk submits request, Manager operational approval, Finance financial authorization, Clerk final receipt (Decisions U-05.1, U-05.2). If rejected by either reviewer, only excess is rejected; approved quantity received; rejection recorded in audit history (Decision UD-01). |
| FR-008 | System generates low‑stock alert notifications for Manager and Finance Officer on threshold crossing (once per crossing, no duplicates). | Mandatory | Item, Notification | Approved | Fires on any quantity‑changing operation. Mock email dispatched via secure dev mailbox without logging secrets to stdout (NFR-009). |
| FR-009 | Real‑time updates pushed to front‑end via SSE. Requires JWT authentication via HttpOnly cookie. | Mandatory | Item, Requisition, Notification | Approved | Typed events including `dashboard.updated`. See SSE Event Specification in SRS §4.4. |
| FR-010 | Dashboard displays totals, low‑stock count, recent requisitions, and role-tailored activity feed via `GET /dashboard`; stays updated via `dashboard.updated` SSE event. | Mandatory | Item, Requisition | Approved | Shared layout with role-specific activity feed (Decision U-11). Frontend replaces local state with SSE payload. |
| FR-011 | Authorized management roles (Admin, Manager, Finance Officer) can export inventory to Google Sheet via Quick Export or configurable Custom Export. | Mandatory | Item | Approved | Quick Export exports all matching filtered records across all pagination with standard columns and preserved sort order (Decision UD-04); Custom Export allows selecting columns and filter scope via modal (Decision U-12). Automatic fallback to CSV stream on API failure. |
| FR-012 | System provides OpenAPI (Swagger) documentation at `/api/docs`. | Mandatory | — | Approved | Auto‑generated from NestJS decorators. |
| ~~FR-013~~ | ~~CI/CD pipeline.~~ | ~~Mandatory~~ | ~~—~~ | Removed | Removed — development‑process activity, not system behaviour. |
| FR-014 | Audit log records all state‑changing operations with before/after snapshots and actor full name. | Mandatory | AuditLog | Approved | Primary identifier is actor full name (Decision U-06); soft-deleted item references preserved (Decision U-08); immutable JSON details. |
| FR-015 | Optional: SMA demand forecasting per SKU on dashboard. | Optional | Item | Proposed | Can be omitted if time‑constrained. |
| FR-016 | Good‑to‑have: Interactive Chart.js visualisations. | Good‑to‑have | — | Proposed | Charts can be added after core flow is stable. |
| FR-017 | Notification history, navigation & read status. Clicking a notification navigates directly to target entity and highlights relevant information. | Mandatory | Notification | Approved | Payload stores destination context (`entityType`, `entityId`); destination route and target highlight section are derived deterministically in combination with notification type (Decision U-10). Paginated inbox filtering with single (`PATCH /notifications/:id`) and bulk (`PATCH /notifications`) mark-as-read. |
| FR-018 | Login endpoint rate‑limiting: max 5 attempts per IP per minute; 6th returns HTTP 429. | Mandatory | User | Approved | Prevents brute‑force attacks. |
| FR-019 | CSRF protection via double‑submit cookie pattern. | Mandatory | — | Approved | Non‑HttpOnly `csrfToken` cookie + `X‑CSRF‑Token` header. Missing/invalid → HTTP 403. |
| FR-020 | Input validation & sanitisation against typed DTOs. | Mandatory | — | Approved | Invalid → HTTP 400; strings escaped before DB insertion. |
| FR-021 | Standardized pagination (`page`, `limit`), domain filtering, and role-specific predefined views for list endpoints. | Mandatory | Item, Requisition | Approved | Shared Requisition List screen with role-specific filter presets: Clerk (All, My Requisitions); Manager (Pending Manager, Reviewed, All); Finance (Pending Finance, Reviewed, All); Admin (All) (Decisions U-03, U-09). Query params `page` (default 1) and `limit` (default 50, max 100); response envelope `{ data: [...], pagination: { page, limit, totalCount, totalPages } }`. |
| FR-022 | SSE connection throttling: max 3 concurrent `/events` streams per user. | Mandatory | — | Approved | Excess connections receive HTTP 429. |
| FR-023 | User Management API: list users, change role, deactivate/reactivate, password reset. Cannot self‑deactivate; last‑Admin guard. | Mandatory | User, Role | Approved | Admin‑only. Deactivation invalidates refresh tokens; HTTP 409 if last Admin. |
| FR-024 | Requisition cancellation: creator may cancel own Pending requisition. Status → Cancelled (terminal). | Mandatory | Requisition, AuditLog | Approved | Cancellation applies strictly to creator's own Pending requisitions; no draft state exists (Decision U-01). Notification sent to Manager and Finance. |
| FR-025 | Manual stock adjustment: signed integer via `POST /items/:id/adjustments`. Rejects if result < 0. Triggers alert evaluation. | Mandatory | Item, AuditLog | Approved | Admin and Clerk only. `adjustmentReason` required. |
| FR-026 | Standalone CSV export & fallback: `GET /exports/csv` available to all authenticated roles for physical counts, planning, and audits (also served as fallback on Sheets API failure). | Mandatory | Item | Approved | Returns direct CSV stream; HTTP 502 with CSV download link if called as fallback from Google Sheets. |
| FR-027 | Refresh token endpoint: `POST /auth/tokens/refresh (alias POST /auth/refresh)` with rotation. 7‑day expiry. Old token invalidated. | Mandatory | User | Approved | Prevents token reuse. |
| FR-028 | Logout endpoint: `DELETE /auth/sessions (alias POST /auth/logout)` invalidates refresh token, clears cookie. | Mandatory | User | Approved | Immediate session termination. |
| FR-029 | Password recovery mechanisms: self-service email-based reset and Admin-initiated reset via `POST /users/:id/temporary-passwords (alias PATCH /users/:id/reset-password)`. | Mandatory | User | Approved | Dual recovery supported (Decisions U-13, UD-02). Self-service uses secure dev mailbox without token logging; Admin-assisted reset requires internal identity verification, generates single-use temporary password (expires after 24 hours), communicated out-of-band (email not required), with mandatory password change at next login (`mustChangePassword: true`). Zero credential logging per NFR-009 (Decision UD-02). |
| FR-030 | Dashboard aggregation endpoint: `GET /dashboard` returns totals, low‑stock count, recent requisitions, and role-specific activity feed. | Mandatory | Item, Requisition | Approved | Role-tailored activity feed embedded in aggregate response (Decision U-11). On‑demand computation; SSE `dashboard.updated` event keeps it current. |
