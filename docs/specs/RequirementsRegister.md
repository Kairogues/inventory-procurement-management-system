# Requirements Register

*Last updated: 2026‑11‑15 (aligned with official baseline SRS v1.2)*

| ID | Requirement | Category | Related Entity | Status | Notes |
|----|-------------|----------|----------------|--------|-------|
| FR-001 | User can register and log in using email and password. New users receive the Inventory Clerk role by default. | Mandatory | User, Role | Approved | Password stored as bcrypt hash; JWT access (15 min) & refresh (7‑day, rotated) tokens in HttpOnly cookies. |
| FR-002 | System enforces role‑based access control for all API endpoints. | Mandatory | Role, User | Approved | Admin, InventoryClerk, Manager, FinanceOfficer roles. See RBAC matrix in SRS Appendix A. |
| FR-003 | CRUD operations for inventory items. Deletion restricted when item is referenced by requisitions. | Mandatory | Item | Approved | Catalog updates (`PATCH /items/:id`) modify metadata and thresholds but cannot alter `quantity`. Manual stock changes require `PATCH /items/:id/adjust` (FR-025) or Goods Receipt (FR-007). Soft-delete via `isActive` flag. Low-stock alerts trigger on threshold crossing. |
| FR-004 | Inventory Clerk can create a purchase requisition with one or more line items. `totalAmount` computed as Σ(requestedQty × snapshotted unitPrice). | Mandatory | Requisition, RequisitionItem | Approved | `unitPrice` captured at creation time; not affected by later price changes. `approvedQty` defaults to `requestedQty`. |
| FR-005 | Manager can approve or reject a pending requisition (first‑level). May modify `approvedQty` (partial approval). | Mandatory | Requisition, AuditLog | Approved | On rejection: reason required; creator may resubmit via `PATCH /requisitions/:id/resubmit` (captures fresh snapshot price). Status transitions use `SELECT FOR UPDATE`. |
| FR-006 | Finance Officer can approve or reject a Manager‑approved requisition (second‑level). May modify `approvedQty`. | Mandatory | Requisition, AuditLog | Approved | On rejection: reason required; creator may resubmit via `PATCH /requisitions/:id/resubmit` (restarts at Pending with fresh price snapshot). Status transitions use `SELECT FOR UPDATE`. |
| FR-007 | Finance Officer can mark a FinanceApproved requisition as Received, incrementing item quantities by `approvedQty`. | Mandatory | Requisition, Item, AuditLog | Approved | Transactional update; `totalAmount` finalized as Σ(approvedQty × snapshotted unitPrice). |
| FR-008 | System generates low‑stock alert notifications for Manager and Finance Officer on threshold crossing (once per crossing, no duplicates). | Mandatory | Item, Notification | Approved | Fires on any quantity‑changing operation. Mock email via console log. |
| FR-009 | Real‑time updates pushed to front‑end via SSE. Requires JWT authentication via HttpOnly cookie. | Mandatory | Item, Requisition, Notification | Approved | Typed events including `dashboard.updated`. See SSE Event Specification in SRS §4.4. |
| FR-010 | Dashboard displays totals, low‑stock count, recent requisitions via `GET /dashboard`; stays updated via `dashboard.updated` SSE event. | Mandatory | Item, Requisition | Approved | No charts for MVP. Frontend replaces local state with SSE payload. |
| FR-011 | Authorized management roles (Admin, Manager, Finance Officer) can export inventory to Google Sheet via `POST /export/google-sheet` (one‑way export; read/write scope). | Mandatory | Item | Approved | Returns `{ sheetUrl }` on success (HTTP 200); HTTP 502 on failure with CSV fallback. |
| FR-012 | System provides OpenAPI (Swagger) documentation at `/api/docs`. | Mandatory | — | Approved | Auto‑generated from NestJS decorators. |
| ~~FR-013~~ | ~~CI/CD pipeline.~~ | ~~Mandatory~~ | ~~—~~ | Removed | Removed — development‑process activity, not system behaviour. |
| FR-014 | Audit log records all state‑changing operations with before/after snapshots. | Mandatory | AuditLog | Approved | Immutable JSON details; includes `rejectionReason` when applicable. |
| FR-015 | Optional: SMA demand forecasting per SKU on dashboard. | Optional | Item | Proposed | Can be omitted if time‑constrained. |
| FR-016 | Good‑to‑have: Interactive Chart.js visualisations. | Good‑to‑have | — | Proposed | Charts can be added after core flow is stable. |
| FR-017 | Notification history & unread flag. Users can view and mark own notifications as read. | Mandatory | Notification | Approved | UI notification panel with unread filter. Supported via `PATCH /notifications/:id/read` (individual) and `PATCH /notifications/read` (bulk with `{ ids, all }`). |
| FR-018 | Login endpoint rate‑limiting: max 5 attempts per IP per minute; 6th returns HTTP 429. | Mandatory | User | Approved | Prevents brute‑force attacks. |
| FR-019 | CSRF protection via double‑submit cookie pattern. | Mandatory | — | Approved | Non‑HttpOnly `csrfToken` cookie + `X‑CSRF‑Token` header. Missing/invalid → HTTP 403. |
| FR-020 | Input validation & sanitisation against typed DTOs. | Mandatory | — | Approved | Invalid → HTTP 400; strings escaped before DB insertion. |
| FR-021 | Standardized pagination (`page`, `limit`) and filtering for list endpoints. | Mandatory | Item, Requisition | Approved | Query params `page` (default 1) and `limit` (default 50, max 100); response envelope `{ data: [...], pagination: { page, limit, totalCount, totalPages } }`. Requisition filters: `status`, `creatorId`. Item filters: `search` (SKU/name), `location`, `stockStatus` (`low` where quantity < reorderThreshold, `normal` where quantity >= reorderThreshold), and `status` (`active` \| `inactive` \| `all`, Admin-only for inactive/all). |
| FR-022 | SSE connection throttling: max 3 concurrent `/events` streams per user. | Mandatory | — | Approved | Excess connections receive HTTP 429. |
| FR-023 | User Management API: list users, change role, deactivate/reactivate, password reset. Cannot self‑deactivate; last‑Admin guard. | Mandatory | User, Role | Approved | Admin‑only. Deactivation invalidates refresh tokens; HTTP 409 if last Admin. |
| FR-024 | Requisition cancellation: creator may cancel a Pending requisition. Status → Cancelled (terminal). | Mandatory | Requisition, AuditLog | Approved | Notification sent to Manager and Finance. |
| FR-025 | Manual stock adjustment: signed integer via `PATCH /items/:id/adjust`. Rejects if result < 0. Triggers alert evaluation. | Mandatory | Item, AuditLog | Approved | Admin and Clerk only. `adjustmentReason` required. |
| FR-026 | Standalone CSV export & fallback: `GET /export/csv` available to all authenticated roles for physical counts, planning, and audits (also served as fallback on Sheets API failure). | Mandatory | Item | Approved | Returns direct CSV stream; HTTP 502 with CSV download link if called as fallback from Google Sheets. |
| FR-027 | Refresh token endpoint: `POST /auth/refresh` with rotation. 7‑day expiry. Old token invalidated. | Mandatory | User | Approved | Prevents token reuse. |
| FR-028 | Logout endpoint: `POST /auth/logout` invalidates refresh token, clears cookie. | Mandatory | User | Approved | Immediate session termination. |
| FR-029 | Admin‑initiated password reset via `PATCH /users/:id/reset-password`. Temp password logged to console. | Mandatory | User | Approved | Self‑service password reset out of scope for MVP. |
| FR-030 | Dashboard aggregation endpoint: `GET /dashboard` returns totals, low‑stock count, recent requisitions. | Mandatory | Item, Requisition | Approved | On‑demand computation; SSE `dashboard.updated` event keeps it current. |
